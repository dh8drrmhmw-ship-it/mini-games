# 决策记录

每条记录写清：决定了什么、为什么、什么情况下可以重新考虑。改决定时不删旧记录，新增一条说明。

### D-001 做免费的微信小游戏，靠广告赚钱（2026-11-05）

- **决定**：做微信小游戏，以个人身份上线。只做免费游戏，靠广告（主要是玩家自愿看的激励视频）赚钱，游戏里不卖任何东西。
- **理由**：发起人选择，从足球经理项目转过来（见 football-sim 仓库决策记录 D-020）。小游戏一款只要几天到几周，不火就换下一款，适合一个人加 Claude 的规模。游戏里卖东西需要版号，个人拿不到；免费、只有广告的游戏个人可以上线，但要软件著作权登记（软著）和备案（第三方资料，正式操作前以微信官方为准，见 `docs/上线流程.md`）。
- **重新考虑的条件**：以后注册了公司、拿得到版号，再考虑卖东西。

### D-002 原创：熟悉的玩法加新点子，不照搬（2026-11-05）

- **决定**：可以学现有游戏的玩法类型，但每款要有自己的新点子；不照搬任何现有游戏的名字、美术、关卡、文案和代码，不做「换皮」；不用需要授权的人物、作品和品牌。
- **理由**：抄袭会被投诉下架；同样的东西原版已经有了，玩家没理由换；也是项目的原则。

### D-003 仓库公开，测试链接用 GitHub Pages（2026-11-06）

- **现状**：仓库建好时是私有的。发起人确认要公开（2026-11-06 回复「公开」），但改设置要发起人自己在 GitHub 上操作。改好之前，测试链接临时发布在 claude.ai 上（只有发起人能打开）。2026-11-06 发起人已改成公开，Pages 部署生效。
- **决定**：仓库 `mini-games` 公开。自动检查通过后，测试页自动部署到 https://dh8drrmhmw-ship-it.github.io/mini-games/ ，不用登录，朋友也能直接打开试玩。
- **理由**：发起人选择（推荐项）。小游戏要靠朋友试玩判断好不好玩，链接必须谁都能开。被抄的风险小：没人盯着一个新仓库，游戏上了微信以后代码本来也能被拆出来；真正的优势是先做出来、先上线。
- **代价**：代码和点子所有人都能看到。不要在仓库里放任何密钥、账号信息或个人信息。
- **重新考虑的条件**：某一款有了明显会火的苗头，在上线前不想让点子提前曝光。

### D-004 技术：TypeScript 加 Canvas 2D，不用游戏引擎（2026-11-06）

- **决定**：用 TypeScript 写，画面用 Canvas 2D，不用 Cocos、Laya 等游戏引擎。同一份玩法代码，一边构建成浏览器测试页，一边打包成微信小游戏。玩法代码不直接碰浏览器接口，画面、触摸、存档、声音、广告都经过平台层，由代码检查自动拦截违规写法。工具和足球经理项目一样（TypeScript 6、Vite 8、Vitest 5、ESLint 10，见足球项目决策记录 D-013）。
- **理由**：Claude 在云端开发，用不了需要图形界面的引擎编辑器；休闲小游戏的画面 Canvas 2D 够用；不带引擎包更小，微信小游戏首包有大小限制，加载也更快。
- **重新考虑的条件**：某款游戏需要 3D 或大量特效，Canvas 2D 做不好。

### D-005 开发方式（2026-11-06）

- **决定**：和足球经理项目一样：Claude 在云端写代码、测试、部署；发起人用手机和 Mac 试玩、反馈、做决定；设计和进度写在仓库里，不依赖聊天记录。本地检查全部通过后直接推送到 main，不开 Pull Request。
- **理由**：发起人不审代码；每个新会话从 main 开始，靠仓库里的文档接上。

### D-006 每款游戏的流程和止损（2026-11-06）

- **决定**：点子 → 原型（手机能玩的测试链接）→ 发起人和朋友试玩 → 打磨 → 做成微信小游戏包 → 发起人上传、提审 → 看数据。原型阶段的判断标准：试玩的人里，有没有人不用催、自己又玩了第二次。没有就换下一款，不硬磨。
- **理由**：小游戏的优势是每次下注小。好不好玩只能靠真人试，Claude 判断不准。

### D-007 只做中文界面（2026-11-06）

- **决定**：游戏只做中文，不做中英双语。
- **理由**：微信小游戏的玩家基本都用中文，双语会多出一倍文字工作。这是 Claude 的默认做法，发起人可以改。
- **重新考虑的条件**：要上海外平台。

### D-008 第一款做「奶茶调配」（2026-11-06）

- **决定**：第一款游戏做点子 1「奶茶调配」（倒水的玩法，加「按顾客的菜单调分层奶茶」）。第二款打算做点子 2「点球大战：会记仇的门将」。
- **理由**：发起人选择（推荐项）。第一款最要紧的是把上线的整条路走通；奶茶做得最快、风险最小，倒水类已有个人开发者做到一万多人在玩。
- **重新考虑的条件**：原型试玩没人主动玩第二次（D-006），就换点球。

### D-009 奶茶调配的关键设计（2026-11-06）

- **决定**（详见 `docs/奶茶调配.md`）：
  1. 关卡提前生成好、固定不变，每关电脑先解一遍保证有解；难度按「最少要在瓶子之间倒几次」逐关上升，每 5 关轻松一关。
  2. 广告只放在玩家自己想要帮助的地方：撤回次数用完（每关免费 5 次）、加一个空瓶（每关最多一次）。不在过关、开局时强塞广告。
  3. 电脑随时检查「还能不能过关」，确定走不通就马上告诉玩家。
- **理由**：榜单拆解（`docs/点子.md`）：卡住时看广告换帮助是个人开发者的赚钱方式，强塞广告会被骂；在死局里白费力气是这类游戏最劝退的时刻。
- **重新考虑的条件**：试玩反馈觉得太难、太简单，或者觉得「走不通」提示是剧透。

### D-010 奶茶调配搁置，第二款做「点球大战：会记仇的门将」（2026-11-07）

- **决定**：奶茶调配试玩后发起人觉得「有点无聊，缺少趣味性」，按 D-006 不硬磨，先搁置（代码和测试页保留）。改做点子 2「点球大战：会记仇的门将」，设计见 `docs/点球大战.md`。
- **理由**：发起人选择（推荐项）。点球的乐趣一上手就能感觉到；发起人懂足球，最会判断好不好玩。
- **重新考虑的条件**：点球也试玩没意思，就回到 `docs/点子.md` 出新点子。

### D-011 每款原型从第一版就要有「手感、压力、奖励、惊喜」（2026-11-07）

- **决定**：以后每款游戏的第一个原型就要带上：手感（声音、动作、震动、做对时「爽」的一下）、压力（会输、有限的机会）、奖励（分数、称号、纪录、过关后有东西拿）、惊喜（新东西出现、角色的反应）。没有这四样，不拿给发起人试玩。
- **理由**：奶茶调配的教训（`docs/奶茶调配.md`「试玩反馈」）：原型只有规则、没有这四样，玩起来就是在做题，判断不出这个点子好不好玩。
- **做法**：声音先用程序合成（不用素材、没有版权问题）。

### D-012 点球大战：选球员、弧线球、力量看划的速度（2026-11-07）

- **决定**（详见 `docs/点球大战.md`）：
  1. 每局开始前选球员，力量、精准、弧线三项 1～5 星，有强有弱；前三个直接能用，后两个靠累计进球解锁，没解锁的可以看广告试用一局。
  2. 画弯就是弧线球：球先沿最开始划的方向飞，再拐到松手的位置；弯越大，门将越难调整，但也越容易偏。
  3. 力量看松手前那一下划得多快，踢出去显示球速。
  4. 苹果手机静音键开着时也出声，游戏里有声音开关。
- **理由**：发起人看录屏后提出前三条；第 4 条是发起人没回答，按推荐做的（方便试玩时听到效果）。
- **重新考虑的条件**：发起人或朋友觉得静音时出声打扰人，就改回跟着静音键走。

### D-013 点球大战改成闯关；惯用脚、球鞋；更多有特点的球员和门将（2026-11-08）

- **决定**（详见 `docs/点球大战.md`）：
  1. 闯关：十关一关一个门将，每关进 5 个过关、3 次机会；从闯到的那关接着打，过关给星星，每过一关解锁一个球员或一双球鞋。取代原来「一局 3 次机会、进越多越好」的玩法。
  2. 惯用脚和逆足：每个球员有惯用脚和逆足星数，可以随时换脚；顺脚的弧线方向弯得大，反方向只能弯一点。画面里画出罚球的脚和球鞋。
  3. 球鞋六双，加在球员能力上。
  4. 球员八个，每人一个绝招；门将十个，高矮胖瘦、穿着、发型、脾气都不一样。
  5. 力量改成看这一划最快的时候有多快。
- **理由**：发起人看第二段录屏后提出前四条；第 5 条是录屏里看到的问题。
- **重新考虑的条件**：试玩觉得关卡太难、太简单，或者解锁太慢。

### D-014 点球大战加难度：不画落点、死角难踢、门将会等球、有风（2026-11-08）

- **决定**（详见 `docs/点球大战.md`）：
  1. 落点预览只在前两关有；从第 3 关起只画开头一小段。
  2. 越往死角瞄偏差越大，大力踢死角最容易偏出。
  3. 门将有两种扑法：猜，或者站着等球（看清方向再扑，最远扑到一定距离）；后面的门将等球越来越多。
  4. 第 4、6、8、9、10 关有风，要自己顶着风瞄。
  5. 平衡用「高手」模拟玩家来调：高手第 1 关约九成过、第 10 关约两成过。
- **理由**：发起人第三段录屏里第 9 关 4 个全进，觉得太简单、没有挑战性。
- **重新考虑的条件**：普通玩家卡得太死（比如朋友试玩大多过不了第 3 关）。

### D-015 点球大战加「进阶操作」（像实况足球），做成默认（2026-11-08）

- **决定**：加进阶操作并设为默认：拖动瞄准（左右、高低，只显示开头一段轨迹）→ 按住射门键蓄力、松手（蓄过头会飞）→ 松手时侧滑是弧线 → 助跑中还能改方向（改得多会偏）；门将在助跑时可能提前扑或者做假动作。原来的「划一下」保留为简单操作，可以切换。下一步做任意球。
- **理由**：发起人选 A（推荐项）：操作手感向实况足球靠，画面和特色走自己的路（`docs/点球大战-调研.md`）。
- **重新考虑的条件**：试玩觉得进阶操作太难上手，就把简单操作改回默认。
